# AGENTS.md — правила для AI-агентов в этом репозитории

Discord-бот: YouTube-ссылка в сообщении → тред с LLM-саммари по субтитрам.
Домашний проект одного сервера, критично: простота запуска и надёжность доставки.

**Перед любым рефакторингом обязательно**: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)
(целевая архитектура и план миграции по фазам) и [docs/TESTING.md](docs/TESTING.md).

## Команды

```bash
# всё через venv репозитория (Windows)
.venv/Scripts/python.exe yt_summary_bot.py        # запуск бота (нужен .env)
.venv/Scripts/python.exe -m pytest                # тесты (без сети, ~1с)
.venv/Scripts/python.exe -m ruff check yt_summary_bot.py tests/
docker compose up -d --build                      # прод-запуск
```

Требования к изменениям: тесты зелёные, ruff чистый. Новая логика → с тестом
(какой уровень — см. «Чек-лист» в docs/TESTING.md).

## Текущее состояние и направление

Код — один файл `yt_summary_bot.py`. Это осознанно до фазы 0; дальше —
постепенный переход на пакет `bot/` по фазам из ARCHITECTURE.md §12
(strangler-паттерн). **Не переписывать всё сразу**: после каждого шага бот
остаётся запускаемым, фазы маленькие.

Ключевые плановые вектора (мотивация всех архитектурных решений):

1. обобщение «YouTube» → «любая ссылка» (статья, целый сайт);
2. отчёт из блоков с прогрессивной детализацией: кратко → тезисно →
   подробно (таймкоды) → обзор автора (кеш + TTL-обновление);
3. SQLite-база разобранных источников и авторов, кеш отчётов.

## Конвенции

- **Язык**: комментарии, докстринги, коммиты, тексты бота и промпты —
  по-русски (как в существующей истории коммитов).
- Комментарии объясняют «почему», не «что» — текущий код этому следует.
- Минимум зависимостей; прод-зависимости в `requirements.txt`, дев — в
  `requirements-dev.txt` (не дублировать).
- Промпты и тексты ошибок — в `prompts.yaml`, подстановка `{transcript}`.
  Меняется формат ответа LLM → поднимай версию промпта (после фазы 1 —
  обязательная часть кеш-ключа, см. ARCHITECTURE.md §6).
- Константы-настройки — env-переменные с дефолтом, читаются только в одном месте.
- Не коммитить: `.env`, `pending_replies.*`, `.venv` (уже в .gitignore).

## Грабли (выученные кровью — не наступать повторно)

- **Docker `network_mode: host` обязателен**: без него DPI рвёт TLS к
  discord.com. Не «чинить» это.
- **entrypoint делает `git reset --hard origin/main`**: любые локальные правки
  в примонтированной папке стираются при рестарте контейнера.
- **exec-бит entrypoint сбрасывается Windows-монтом** — поэтому chmod в
  ENTRYPOINT-обёртке Dockerfile, не убирать.
- **certifi в Docker подменён симлинком на системный CA-стор** — часть
  образа, связана с цепочками конкретного LLM-провайдера.
- **`max_tokens=50000` рассчитан на GLM**; у OpenAI-моделей лимит ниже →
  мгновенные 400. Значение должно стать конфигом (фаза 0).
- **Один LLM-воркер** — не добавлять параллельные LLM-вызовы без общего
  rate limiter'а; провайдер лимитирует.
- **160004** («тред уже существует») — обрабатывается переиспользованием
  треда, не ошибкой. Сохранять это поведение.
- Python: локально 3.14, в Docker 3.12 — писать код, совместимый с 3.12
  (`target-version = py312` в ruff).
- venv локальный может отставать от `requirements.txt` (так было с pyyaml) —
  если импорт падает, сначала `pip install -r requirements-dev.txt`.

## Тестирование

- В CI и обычном прогоне — **без сети**: Discord/LLM/субтитры подменяются
  фейками (примеры в `tests/`, подход в docs/TESTING.md).
- Тесты с реальными токенами — только маркер `live`, только вручную.
- Для пользовательски видимого поведения (сообщения в тред) — e2e-сценарий
  в `tests/e2e/`, не юнит внутренностей.
